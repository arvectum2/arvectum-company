# AEC-001 — Portable local Git inventory: read-only, bounded scope

Date: 22 November 2026. Candidate Company engineering utility. **Not** an approval to scan all attached computers, access customer sources, change live services or treat the inventory as an organization registry.

This small extraction comes from the larger draft AEC-001 PR #47 at source commit 387b68694e875457eef94225b9bc357ae361aafd. The module, tools/aec001_inventory.py, reads Git metadata for directories explicitly supplied using --root and may hash a bounded subset of Git-tracked source files to identify duplicate content across repository identities. It does **not** execute repository source code, fetch remotes, modify a worktree, update an organizational model or delete any worktrees. The reported repository identity can be inferred from Git remote URLs; credentials embedded in remotes are not intentionally emitted.

Output can expose local project names, repository structure and source metadata. Therefore **all actual output is private evidence**; it must not be uploaded to Git, a shared PR or public CI logs. For a local authorized execution, supply --root to a directory with Git checkouts and --output to a private non-Git destination, e.g. under a protected ArvectumSafe audit folder. Without --output the report is written to stdout and should be used only in a secured terminal. Output files use atomic replacement and mode 0600 and are refused inside a Git worktree or through a symlink destination.

The scoped GitHub Actions job executes only synthetic/offline unit tests; no production roots or real repository inventories are scanned in CI. Offline tests verify that worktree counts are read-only, the same remote is not counted twice as a distinct repository, Git remote credential details are not leaked in the identity, a symlink cannot redirect a report, an in-worktree output is refused, tracked symlinks cannot read outside a repository, and files remain 0600.

**Limitations:** Repository inventory is not live deployment evidence, a validated license/secret scan, a custody chain, an approved data rights finding or proof of service health. Full ecosystem provenance, actual backup recovery and Product rollout remain separate blocked AEC-001 gates. ## Final isolated PR review refinements — 2026-11-22

Remote identity parsing now trusts only the exact github.com or gitverse.ru hostname (HTTPS/SSH/SCP forms), rejecting lookalikes, embedded credential distractions and malformed URLs instead of attributing them to a canonical Product. Both the lexical user-supplied path and resolved report destination are rejected if their ancestry is inside Git, including symlink escapes, gitdir files and broken symlink markers. New report directories request mode 0700. Local Git commands run with GIT_OPTIONAL_LOCKS=0 to avoid optional Git index refresh writes. These are conservative security/side-effect protections; they do not prove hostile-filesystem race resistance, a Git source provenance chain or user authority over any scanned repo.
