## 3. Минимальный контракт управленческой карточки (proposal)
Стабильная ссылка на существующий governed ID либо кандидат без нового ID; тип работы; объект/владелец и источник; бизнес-цель; текущий результат и стадия; 3–7 существенных вех с критерием завершения (unknown допустимо); следующие 1–3 проверяемых результата; срок (или unknown), зависимости/блокировки; исполнитель/полномочия (unknown не делает задачу автономной); класс очереди (autonomous_candidate, owner_action_candidate, waiting_external, deferred, reconciliation_required); причина/условие возобновления; следующий review trigger; evidence refs и as-of; coverage, freshness, конфликт, финансовые/договорные ограничения. Факты отделить от рекомендаций. Не придумывать проценты готовности. Не отображать raw customer data/секреты. Отсутствие источника — неизвестно, не зелёный статус.

## 4. Последовательность работ (не новые канонические roadmap IDs)
1. Reconciliation — проверить открытые ветки AC-405/407, согласовать scope; собрать полный cross-project inventory с source refs, включая обязательства и клиентские возможности отдельно от PORT.
2. Project brief pilot — сначала Музей Хлеба, Балтика, Proxy Launcher, MAX2TG, Tender Agent: конкретная цель, milestones, next actions, waiting conditions, source versions; сверить свежие факты с настоящими источниками и разрешённым контекстом, не переносить конфиденциальное содержимое в Git.
3. Company control — перечень подтверждённых обязанностей в AC-401; решения/риски в AC-402/403; финансовые сигналы AC-404; portfolio reassessment AC-405. Не создавать конкурирующие регистры, не назначать приоритеты исполнительным предложением.
4. Projection — подготовить read-only structured derived view с проверкой полноты, свежести, ссылок, конфликтов и очередей в Company scope. Сначала проверить фактическое использование руководителем; OS integration только через действующий/расширенный WSF-05 boundary по OS governance.
5. UI — обзор компании → проекты → milestones/next actions → source evidence / machine roadmap. Пустые поля заменить явным reconciliation needed, не выдуманными задачами.
6. Cadence — обновление по существенному событию и регулярным существующим AC-407 checkpoints; ежедневное чтение по желанию, не обязательная церемония. После работы технический результат проверяется и отражается в source, проекция пересчитывается; ожидание внешнего события имеет trigger.
7. Acceptance — проверка собственником на реальных проектах: увидеть цель, состояние, что дальше, кто действует, сроки/риски/ожидания, источник за 2–3 минуты; нет потерянных активных работ; все профили unknown/blocked честны; нет автоматического повышения полномочий. Измерить результат, не заявлять PASS по одному UI.

Приоритет предложения: обязательства и continuity прежде коммерческих возможностей, затем продуктовые работы с подтверждённой ценностью; не отменяет approved Workspace First: core contour + bounded blocker + consumer side lane. Никаких новых расходов, релизов, заявок, коммерческих сообщений или межрепозиторных обязательств по этому документу.
