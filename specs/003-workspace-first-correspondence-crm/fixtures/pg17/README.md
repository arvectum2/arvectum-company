# Isolated PostgreSQL 17 design fixture

Candidate CR-T003/004 evidence only. Not a production migration, Product Contract, new runtime or authority. The SQL tests use synthetic tenants, test-only trust auth on a Unix socket in a network-disabled disposable container, and a read-only mount containing only fixture files. Never expose this configuration or fixture roles in production. Use locally available PostgreSQL 17 image, pinned to the actual reviewed image; no pulls or production connections. The tests require a disposable data directory, no shared volumes, and no real correspondence. Run from a private scratch directory; do not publish generated SQL or actual SQLite files.

Files: schema.sql, test.sh, sqlite_to_pg.py (read-only offline seed SQL generator), make_fixture.py (synthetic seed, deliberately damages its own fixture after generating SQL to test rejection), test_migration.sh. Run make_fixture.py once in a fresh scratch directory, then run the two shell scripts in separate disposable PG17 containers with that directory mounted read-only at /fixture. Use `--rm --pull never --network none --user postgres --entrypoint bash --memory 512m --cpus 1`; no production data mounts. Do not run against existing cluster. Migration generated SQL must be kept private when based on an authorized real seed.
